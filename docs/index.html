LinkedIn Scout

A tool I built to find who to reach out to at a company, ranked by how well their background matches my resume.

Rishav Dutta · Built February 2026 · Updated October 2026

Try it (no sign-up) → Source on GitHub →

Why I built it

During my MBA job search, networking took most of my time. For every company on my list I searched LinkedIn for people in the team I wanted to join, opened profile after profile, and tried to work out whose background was close enough to mine that a message would get a reply. It was slow, and I was mostly guessing.

I wanted to type in a company and a role and get back a short list of people, in order, with a reason for each one. So I built that.

What it does

  1. Search. Enter a company and a role, for example “Airtable” and “Product Manager”.
  2. See who works there. Matching LinkedIn profiles show up in about a second. Photos and full profiles fill in over the next few seconds.
  3. Rank them. Upload your resume as a PDF. Gemini scores each person from 0 to 100 against it and writes a sentence or two on why.

How it works

There is no custom backend server. The site is a React app on Vercel, and the work happens in two n8n workflows that I self-host. The browser never talks to n8n directly; every request goes through a small Supabase function first.

Browser (React, Vercel)
→ Supabase Edge Function checks the input, applies rate limits, adds a secret
→ n8n (Oracle Cloud free tier)
→ Firecrawl to search, Apify to fetch profiles, Gemini to score
→ results saved to Supabase Postgres, which the site reads back

Searching. n8n runs a web search for public LinkedIn profiles at the company, saves the people it finds and replies to the site straight away. It then fetches each person’s full profile in the background.

Scoring. n8n pulls the text out of the resume and sends it to Gemini along with each profile, labelled with its database ID. Gemini returns a score and a reason for each ID, and n8n saves them.

What broke, and what I changed

The first version worked in a demo. These are the problems that showed up after that, and how I fixed them.

Anyone could spend my API credits

The site called the n8n webhooks straight from the browser, so anyone who opened the developer tools could run paid searches in a loop. The leads table was also publicly readable. Now a Supabase Edge Function sits in front of n8n: it validates input, allows 5 searches and 10 uploads per visitor per hour, and is the only thing holding the key n8n accepts. The browser reads results through one database function that returns a single search’s rows.

Searches took up to 35 seconds

Timing each step showed that fetching full profiles took over 90% of the time. The search itself is quick, so the workflow now replies as soon as it has names and links. Contacts appear in about a second, and the resume upload unlocks once the full profiles arrive.

Some people silently disappeared

When someone had changed their LinkedIn URL, the scraper returned the new address, and my database update looked for the old one. The person stayed on screen with no profile and never got scored. The workflow now matches on the exact URL it sent and then stores the current one.

Gemini mistyped a URL

I originally asked Gemini to copy each person’s LinkedIn URL back with their score. Once it dropped two characters, and that person’s score was lost. Now each profile goes in with its database ID, and only IDs that were sent are accepted.

Gemini sometimes returns nothing

About one request in five came back empty, which failed the whole upload. The scoring step now retries up to five times. I also found that n8n ignores the retry setting on the model itself; only the setting on the agent around it takes effect.

A typo looked like a crash

A misspelled company name returned no results, and the site said “Search failed”. It now says nobody was found and suggests checking the spelling.

I was paying for a server that sat idle

n8n started on a small DigitalOcean server. I moved it to Oracle Cloud’s free tier, gave it a public HTTPS address through Tailscale Funnel and set up monthly backups. The whole project now runs on free plans.

What I left out

There are no accounts and no saved search history. I left both out so I could ship the whole flow end to end first. Searches cover US profiles and return up to four people each, which keeps scraping costs low.

Stack

FrontendReact 18, TypeScript, Vite, Tailwind CSS, on Vercel
GatewaySupabase Edge Function (Deno)
Workflowsn8n, self-hosted in Docker on Oracle Cloud
AIGoogle Gemini 2.5 Flash-Lite, through n8n’s AI Agent with structured output
Search and profilesFirecrawl (web search), Apify (LinkedIn profile scraper)
DataSupabase Postgres and private storage, with versioned migrations
ChecksGitHub Actions: lint, type check and build on every pull request

The code, database migrations and both n8n workflows are in the GitHub repo, with steps to run your own copy.
